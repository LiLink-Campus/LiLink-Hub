# LiLink 运营工作台 · 用户引导（Onboarding）UX 设计

- 日期：2026-06-03
- 状态：草案（待 review）
- 关联：[运营内容工作台设计](2026-05-31-operator-content-studio-design.md)
- 缘起：用户实测「第一次进去完全看不懂怎么操作」，且从首页误入原生 `/admin`。本设计补「从进门到上手」的引导链路，不重做工作台。

## 1. 背景与诊断

9 个 agent 从「零基础校园运营第一次打开」视角并行审计了 `/studio` 全流程，核心断点：

- **正门焊死、只留后门**：首页 `/` 唯一按钮「进入后台 →」指向原生 `/admin`（设计 §1 明令「运营永不接触」），且全站无 middleware 兜底、首页无 `/studio`/`/login` 入口。这是唯一的**硬阻断**，也是用户绕晕的直接原因。
- **三步心智隐性**：`创作▸发布▸审核` 是核心心智，但 StepHeader 纯装饰、不可点也无说明；新人不知道"现在第几步、做完去哪"。
- **首次零引导**：登录后空账号首屏只有"还没有内容"一句，没有"这工具干嘛、一条内容从写到发走哪几步"的总览。
- **选形式打架**：长文卡 desc"图文并茂"与隔壁"图文"卡正面冲突，运营按平台/目标思考却被迫理解内部"形式"术语。
- **术语黑话**：发布配置/发布包/形态、"审核队列"对单人运营（自己写自己审）没点破身份。

## 2. 设计核心

**把现有微光玫瑰工作台的「创作▸发布▸审核」三步心智从隐性变显性。** 不新增页面、不碰后端与 `/admin`，只改首页入口 + 在 `/studio` 层补 5 类轻量引导件，全部复用现有 `_ui`/`_lib/theme`。

## 3. 改动清单（按优先级）

### P0 — 唯一硬阻断，必先做

1. **入口治理 · 首页服务端分流**（`app/(app)/page.tsx`）：删掉指向 `/admin` 的黑按钮与 system-ui 灰黑样式，改为最薄的服务端重定向——`getCurrentUser()` 已登录 `redirect('/studio')`、未登录 `redirect('/login')`（复用 studio/login 既有鉴权闭环）。运营从根域名永远直达正确去处，再不会看到裸落地页或误入 `/admin`。本页只 redirect 不渲染外壳。

### P1 — 断链 / 误导，应做

2. **入口治理 · 登录 next 回跳**（`studio/_lib/auth.ts`、`login/page.tsx`）：`requireUser()` 把裸 `redirect('/login')` 改为带原路径 `?next=`；登录页读 `next`、成功后回跳（同源 `/` 开头白名单防开放重定向）。消除"从深链被踢回登录、登完上下文丢了"。
3. **首次欢迎引导 · 首屏一次性新手卡**（`studio/page.tsx` + 新增 `'use client'` 小组件）：StepHeader 与「我的内容」之间放一张可关闭的「① 创作（只管写）② 发布（选平台补信息）③ 审核通过后一键发出」流程总览卡，复用 `_ui` Card + 📄🖼🎬，关闭态记 localStorage，仅空账号/未关闭时显示。
4. **空状态强引导 · 工作台**（`studio/page.tsx` EmptyState）：hint 改为讲清闭环"点开始创作选形式就能写、自动存草稿 → 发布页选平台补信息提交审核 → 通过后长文发公众号草稿/图文视频生成发布包"，并补"不确定选哪种？长文=公众号，图文=小红书，视频=抖音/视频号"反向指引。
5. **空状态强引导 · 选形式页**（`studio/create/page.tsx`）：三卡上方加"按你想发的平台来选"反向指引；修长文卡 desc（去掉"图文并茂"、改"一篇正经推文，一键发公众号草稿箱"），图文卡强调"以图为主的种草笔记"，消除长文/图文打架。
6. **流程自解释 · StepHeader micro-copy**（`studio/_ui/index.tsx`）：三步每步补一句（创作=只管写好内容/发布=选平台填信息/审核=通过后才正式发出），当前步保持玫瑰高亮但不做成可点导航；修正"我的内容"总览页不再误高亮"创作"。
7. **流程自解释 · 顶栏 active 高亮**（`studio/layout.tsx` + `'use client'` 导航子组件用 `usePathname`）：当前栏淡玫瑰 pill + `aria-current`，让新人随时知道"我在哪、点哪回去"。
8. **术语友好 · 点破审核身份**（`studio/review/page.tsx`、`ReviewList.tsx`）：页头与空状态改第二人称"在 LiLink 你既是创作者也是审核者：提交的稿件到这里由你通过/打回，通过后发布"。不改权限模型（v1 全能运营）。

### P2 — 打磨

9. **术语友好 · 白话化残留黑话**（`publish/[id]/PublishEditor.tsx` 等）：「发布配置」→「发布/准备发布」并点明"填好点提交审核、通过才真正发出"（名实对齐，底部按钮本就是"提交审核"）；"暂无开放发布接口"→"这几个平台还不能自动发布，通过后生成发布包你自己复制去发"；"人工发布包"括注白话；对外统一叫"形式"。
10. **入口治理 · 归位孤立的 `/studio/queue`**（`studio/queue/page.tsx`）："发布队列"全站零入口、与"审核队列"近义。本次只做最小决策：要么顶栏加第三导航项 + 与审核页互相指引，要么不给入口保持现状；不重构。
11. **首次欢迎引导 · 登录页**（`login/page.tsx`）：副标题扩成"创作 ▸ 发布 ▸ 审核，登录后只管写"预告心智；页脚"账号由管理员开通"升级为可操作"首次使用？向管理员索取邮箱与初始密码"+ 可点「联系管理员」(env 可配，别写死)。
12. **流程自解释 · compose 创作页定心条**（`compose/{article,imagetext,video}`）：各页头一句一次性引导"这步只管写内容；平台/话题/封面写好后点下一步再设置"，记 localStorage；顺带修长文页过时文案（"右侧手机预览"实际已是单列 Typora 面 → 改"专心写、自动保存、点右上预览成品"）。

## 4. 范围与 YAGNI（out of scope）

- 不做多步交互式 product tour / 浮层 coachmark / 高亮遮罩——一次性可关闭说明卡 + micro-copy 足够。
- 不碰后端数据模型、Payload collections、`/admin`。
- 不改权限/审核模型（v1 同一运营即审核），只用文案点破身份。
- 不把 StepHeader 做成可点导航。
- 不新增全局 middleware（首页分流在 page 层用 `getCurrentUser()+redirect` 完成）。
- 登录可用性打磨（密码显隐、字段级校验移焦、Payload 锁定态错误细分）本次只取"预告三步 + 联系管理员"两项，余下后续单独迭代。
- 不做状态色入 theme、箭头符号统一等纯视觉精致度（留给视觉一致性专项）。

## 5. 实现与验证

- 复用现有 `_ui`（Card/Button/EmptyState/StepHeader/Field）与 `_lib/theme`，不引入新依赖。
- 按 **P0 → P1 → P2** 顺序实现；P0 单独先验证（堵死 `/admin` 误入）。
- **每块改完用 Playwright 打开真实页面截图核对**（用户明确要求"多看浏览器调整"），而非看静态 mockup。
- 不碰后端/渲染/发布器/测试契约，保证零回归；涉及 `'use client'` 子组件抽取时保持 page 的 RSC 性质。
